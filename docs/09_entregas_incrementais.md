# 09. Entregas Incrementais

## 1. Visão geral

Este documento consolida as entregas realizadas ao longo do semestre no desenvolvimento do Sistema de Controle de Estoque.

O projeto foi desenvolvido de forma incremental, seguindo uma adaptação do Scrum ao contexto acadêmico da disciplina de Engenharia de Software. A cada sprint, o grupo avançou em uma parte do trabalho, começando pela definição do problema e organização inicial, passando por requisitos, modelagem, arquitetura, padrões de projeto, implementação, testes e preparação da entrega final.

As entregas registradas neste documento estão alinhadas aos arquivos de sprint do repositório e aos artefatos produzidos durante o desenvolvimento. Ao final do processo, o projeto foi consolidado como uma aplicação web funcional para controle de estoque, acompanhada da documentação técnica necessária para sua apresentação e avaliação.

## 4. Evolução do produto

O Sistema de Controle de Estoque evoluiu de forma incremental ao longo das sprints. Nas primeiras etapas, o grupo definiu o problema, a visão do produto, os stakeholders, o escopo inicial e a organização do trabalho com Scrum.

Depois, o foco passou para o levantamento e priorização dos requisitos, com a criação do Product Backlog, requisitos funcionais, requisitos não funcionais e histórias de usuário. Essa etapa permitiu transformar a ideia inicial em funcionalidades esperadas para o sistema.

Em seguida, o grupo trabalhou na modelagem, arquitetura e padrões de projeto. Foram criados diagramas, decisões arquiteturais e justificativas técnicas para orientar a implementação. Essa base ajudou a definir a separação entre backend, frontend, documentação e módulos principais do sistema.

Nas sprints finais, o projeto evoluiu para a implementação prática. Foram criadas as estruturas do backend e do frontend, as funcionalidades principais foram desenvolvidas, os testes manuais foram registrados e a documentação final foi consolidada.

Ao final, o produto passou de uma proposta documentada para uma aplicação web funcional, com controle de produtos, movimentações de estoque, identificação de estoque baixo, autenticação básica, consulta de movimentações, documentação de apoio, registros de sprint, testes e preparação para apresentação final.

## 5. Mudanças relevantes no escopo

| Mudança | Motivo | Impacto |

| Priorização das funcionalidades essenciais de estoque | O grupo definiu que o núcleo do produto deveria concentrar as funções principais de controle de estoque | O sistema foi consolidado com foco em cadastro, consulta, entrada, saída e estoque baixo |
| Autenticação implementada de forma básica | O controle de acesso foi definido como uma funcionalidade necessária para organizar o uso do sistema | O sistema passou a possuir autenticação básica, com possibilidade de refinamento em versões futuras |
| Consulta de movimentações mantida como base para relatórios | A funcionalidade de relatório foi tratada como acompanhamento das entradas e saídas registradas | O sistema passou a permitir consulta de movimentações, podendo evoluir para relatórios mais detalhados |
| Testes priorizados de forma manual e funcional | O grupo optou por validar os principais fluxos de uso do sistema conforme os requisitos documentados | Foram registrados casos de teste, resultados obtidos e defeitos acompanhados por Issues |
| Uso de Issues para rastreabilidade | O grupo precisava relacionar tarefas, testes, defeitos e melhorias | Melhorou o acompanhamento das atividades e a relação entre requisitos, testes e correções |
| Ajustes finais na estrutura do repositório | A organização precisava ficar coerente com a entrega final | As pastas e documentos foram revisados para facilitar a avaliação e manutenção |

## 6. Conclusão

O desenvolvimento do Sistema de Controle de Estoque ocorreu de forma incremental, permitindo que o grupo evoluísse o projeto em etapas ao longo do semestre. Cada sprint contribuiu para uma parte importante da entrega, desde a definição inicial do problema até a consolidação da aplicação, dos testes e da documentação final.

A organização por sprints facilitou o acompanhamento das atividades e permitiu relacionar os conteúdos da disciplina com a prática de desenvolvimento. O grupo aplicou conceitos de Scrum, requisitos, modelagem, arquitetura, padrões de projeto, implementação e testes, mantendo os principais artefatos documentados no repositório.

Ao final do processo, o projeto apresentou uma solução funcional para o contexto acadêmico, com funcionalidades básicas de controle de estoque, documentação completa e registro das entregas realizadas. Também foram registradas melhorias futuras, como ampliação dos testes automatizados, refinamento da autenticação, evolução dos relatórios e melhorias na interface.
